# Placey - Infrastructure Specification

## Overview

This document details the AWS infrastructure configuration for Placey, a proximity-based place discovery application. It covers networking, compute, data, security, observability, and frontend hosting.

All resources are provisioned in `us-east-1` (N. Virginia) unless otherwise noted.

## Networking

### VPC

| Setting        | Value         |
| -------------- | ------------- |
| CIDR           | `10.0.0.0/16` |
| DNS hostnames  | Enabled       |
| DNS resolution | Enabled       |

### Subnets

| Name                                | AZ         | CIDR          | Tier           | Purpose                                   |
| ----------------------------------- | ---------- | ------------- | -------------- | ----------------------------------------- |
| `placey-dev-subnet-app-us-east-1a`  | us-east-1a | `10.0.1.0/24` | App (private)  | Lambda functions                          |
| `placey-dev-subnet-data-us-east-1a` | us-east-1a | `10.0.3.0/24` | Data (private) | RDS primary, RDS Proxy                    |
| `placey-dev-subnet-data-us-east-1b` | us-east-1b | `10.0.4.0/24` | Data (private) | Required by RDS Proxy (no resources here) |

All subnets are private. There is no public subnet, Internet Gateway, or NAT Gateway — all outbound traffic from Lambda stays within the VPC via VPC Endpoints.

> RDS Proxy requires a DB subnet group with subnets in at least 2 AZs. The AZ-b data subnet exists solely to satisfy this requirement. No application resources are deployed there.

### Route Tables

| Name                 | Associated Subnets                                                       | Routes     |
| -------------------- | ------------------------------------------------------------------------ | ---------- |
| `placey-dev-rt-app`  | `placey-dev-subnet-app-us-east-1a`                                       | Local only |
| `placey-dev-rt-data` | `placey-dev-subnet-data-us-east-1a`, `placey-dev-subnet-data-us-east-1b` | Local only |

### VPC Endpoints

| Name                              | Service         | Type      | Subnets     | Purpose                                 |
| --------------------------------- | --------------- | --------- | ----------- | --------------------------------------- |
| `placey-dev-vpce-secrets-manager` | Secrets Manager | Interface | App subnets | Lambda fetches DB credentials privately |

Private DNS enabled on the endpoint so Lambda can resolve `secretsmanager.us-east-1.amazonaws.com` without leaving the VPC.

## Security

### Security Groups

All security groups are attached to `placey-dev-vpc`. Create all groups first (empty), then add rules — some rules reference other security groups by ID.

#### `placey-dev-sg-lambda`

### IAM Roles

#### `placey-dev-lambda-role`

Trust policy: `lambda.amazonaws.com`

Attached managed policies:

- `AWSLambdaVPCAccessExecutionRole` — ENI management for VPC-attached Lambda
- `AWSLambdaBasicExecutionRole` — CloudWatch Logs write access

Inline policy `placey-dev-lambda-secrets-policy`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "<rds-managed-secret-arn>"
    },
    {
      "Effect": "Allow",
      "Action": "rds-db:connect",
      "Resource": "arn:aws:rds-db:us-east-1:<account-id>:dbuser:<rds-proxy-resource-id>/placey_admin"
    }
  ]
}
```

#### `placey-dev-rds-proxy-role`

Trust policy: `rds.amazonaws.com`

Inline policy `placey-dev-rds-proxy-secrets-policy`:

```json
{

  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "<rds-managed-secret-arn>"
```

## Data

### Secrets Manager

The DB credentials secret is **automatically created and managed by RDS** when `manage_master_user_password` is enabled. AWS names it `rds!db-<instance-id>` and handles rotation automatically (every 7 days by default).

- Secret name: `rds!db-<auto-generated>` (not configurable)
- Managed by: RDS (not Terraform directly)
- Contents: `username`, `password`, `dbClusterIdentifier`, `engine`, `host`, `port`
- Accessed by: Lambda (via VPC Endpoint), RDS Proxy
- Auto-rotation: enabled (managed by RDS)
